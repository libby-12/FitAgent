# FitAgent working agreements

- Explain every code change to Libby in Hebrew: where it was made, what changed, and why. Keep explanations suitable for a student preparing to defend her project before an examiner.
- After changing code, build the Android target and report errors and warnings accurately. Fix build failures caused by the change before declaring completion.
- Obtain approval for each proposed replacement of user-facing text before applying it. Approved replacements do not require repeated confirmation.
- Keep purple as the consistent visual theme across application pages. Reuse the shared brand resources and header when appropriate.
- Do not add code comments stating that code was generated or written with AI assistance. Use ordinary explanatory comments about purpose and behavior when useful.
